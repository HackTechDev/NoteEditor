# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

NoteEditor: a tabbed text editor GUI. Two independent, functionally equivalent implementations live side by side and share the same on-disk data format under `~/.noteeditor/`:

- **`Python/`** — Python + PyQt6. See `Python/CLAUDE.md` for commands and Python-specific notes.
- **`Cpp/`** — C++ + Qt6 (CMake). See `Cpp/CLAUDE.md` for commands and C++-specific notes.

When a feature request doesn't name a language, ask which implementation(s) it applies to rather than guessing — they're kept in sync by convention, not by shared code. A behavior change in one is not automatically reflected in the other.

There is no test suite, linter, or CI configured for either implementation. Verify changes by actually running the app (see each subdirectory's `CLAUDE.md`) — do not assume correctness from reading the code alone, especially anything involving Qt layout/geometry.

### Testing a GUI change

Neither implementation has a headless assertion suite; a manual driver is used instead (see the subdirectory `CLAUDE.md` for how to build/run it per language):

- **Offscreen smoke test** (no display needed): drive the API directly (create a `MainWindow`, call `newTab`/`closeTab` equivalents, assert on state) under `QT_QPA_PLATFORM=offscreen`.
- **Visual check**: render with the widget's `grab()` and save/read back the image. This renders the widget's own paint buffer — it is *not* a screen capture and is safe to use even on a real, shared `DISPLAY`.
- **Never** run a full-screen capture tool (e.g. `import -window root`, `scrot`) against a real `DISPLAY` — if it's the user's actual desktop rather than an isolated virtual one, this captures whatever else is on screen (other windows, private content). Stick to `grab()`.
- When testing session/draft persistence, always override `HOME` to a scratch directory (`env HOME=/tmp/.../fakehome`). The real `~/.noteeditor` is the user's actual data — never write to it from a test run.

## Architecture

### Module map

Same responsibilities in both implementations, just named per-language convention:

| Responsibility | Python | C++ |
|---|---|---|
| Main window, tabs, menus, file I/O | `main.py` (`MainWindow`) | `MainWindow.h/.cpp` |
| Editor widget (line-number gutter, current-line highlight, `session_id`) | `editor_widget.py` (`Editor`) | `Editor.h/.cpp` |

### The `~/.noteeditor` persistence model

This is the part that spans multiple files and isn't obvious from any single one, in either implementation. These live under `~/.noteeditor/`, in a JSON format both implementations read and write identically (they can be pointed at the same home directory interchangeably):

- `session.json` — the tabs currently open (file path if any, default name, modified flag) plus which one is active, and per tab the cursor position and vertical scroll (`cursor`/`scroll`, plus `anchor` when there is a selection — the selection start, `cursor` being its end; all optional and living in `session.json` only, never in `index.json`). Read once at startup to restore the window; rewritten wholesale on every quit.
- `index.json` — accumulated metadata (file path, default name, modified flag) for **every** draft ever seen, keyed by `session_id`, plus an optional `"pinned": true` (absent = not pinned; see "Pinned notes" below) and an optional `"remember": true` (a note that asked to appear in `recent.json` even when empty; `save_draft`/`save_session` carry it over through `_merged_meta`/`mergedMeta`, exactly like `pinned`, and only `set_remembered`/`setRemembered` writes it). Never pruned automatically — entries only disappear via explicit deletion (trashing) from the drafts sidebar.
- `drafts/<session_id>.txt` — the raw text backup for one tab. Written immediately when a tab is created, ~1.5s after each keystroke (debounced, see below), when it's closed (if modified), and unconditionally for every open tab when the app quits.
- `docs/<default_name>.md` — where `Ctrl+S` lands for a tab that has no real file yet (`.md`, so the note gets Markdown highlighting and preview; older notes saved here as `.txt` keep their path). This is a genuinely saved file, not a backup.
- `trash/<session_id>.txt` + `trash_index.json` — where a draft's file and metadata move when "trashed" from the sidebar (soft delete). `index.json`'s entry for that id is removed at the same time; restoring reverses both moves.
- `history/<session_id>.json` — the undo/redo history of a tab open at the last quit, as `{"pos", "length", "steps": [{"at", "del", "ins"}]}`. Written by `save_session`/`saveSession` only, which also deletes every file there whose tab is no longer open (so it never accumulates). Positions are **UTF-16 units** in both languages (Qt's own), so the files are interchangeable; `length` is the UTF-16 length of the current text.
- `versions/<session_id>/<timestamp>.txt` — up to the 10 most recent versions of a file, one snapshot taken of whatever was on disk immediately before each overwrite (i.e. it captures pre-save states, not post-save ones). Pruned to the newest 10 on every write.
- `recent.json` — the notes most recently *closed* (newest first, at most `limit` — 10 by default, 1..50, stored in the same file as `"limit"` and read *before* rewriting the file, which truncates it; `id`, `file_path`, `default_name`), shown in File → « Notes fermées récemment ». Written by `close_tab`/`closeTab` after every successful close (never at quit, never for a note trashed instead of closed, and an *empty untitled* note only when it carries the `remember` flag (« Mémoriser à la fermeture » in the tab and sidebar menus — a note with text or a file is always recorded)); an entry is dropped when the note is opened again (`new_tab`/`newTab`), trashed or deleted (`trash_draft`/`delete_draft`), or when it can no longer be reopened (`list_recent`/`listRecent` filters: an external file must still exist, any other note must still have its draft). Reopening an external file goes through `_open_path`/`openPath` so the *current disk content* is read, not the stale hidden draft.
- `window.json` — the last window size, screen position (`x`/`y`, optional — absent in files written before it existed, and ignored on restore if it no longer intersects any screen) sidebar-splitter position and display settings (`sidebar_visible`, `word_wrap`, `markdown_preview`, all optional — absent means the defaults: sidebar shown, wrap on, preview off), saved in `closeEvent()` and applied at construction time (before the tab session is restored). Unlike everything else above, this is a UI preference, not document data — it's the only thing in `~/.noteeditor/` that isn't keyed by `session_id`. The main splitter (sidebar | editor area) must keep exactly **two** sizes in `window.json`: the shared Markdown preview pane therefore lives in an *inner* splitter (tabs | preview) that is the main splitter's second widget. The sidebar can be hidden from the toolbar (`sidebar_visible: false`, `_set_drafts_panel_visible`/`setDraftsPanelVisible`); its live splitter size is then 0, so `_splitter_sizes_to_save`/`splitterSizesToSave` writes the width it had *before* hiding (kept in `_drafts_panel_width`, captured only once the window is visible — at startup the splitter is not laid out yet and would give a bogus width). Whether the preview is *enabled* is persisted (`markdown_preview`), but the pane itself only shows while the active tab is a Markdown file.

Key invariant: the `drafts/` backup **never** writes to the user's real file location — only an explicit Save/Save As touches a path outside `~/.noteeditor`. Don't blur this line when adding auto-save behavior. This also holds for deletion: `trash_draft`/`trashDraft` and `purge_draft`/`purgeDraft` (`Session.h/.cpp`) only ever touch `drafts/`/`trash/` — the real file at `file_path`, wherever it lives (`docs/` or fully external), is never written to or removed. Both confirmation dialogs (`_trash_draft`/`trashDraftEntry`, `_trash_entries`/`trashEntries`, and `TrashDialog._purge_selected`/`purgeSelected`) say so explicitly whenever the entry (or entries) being acted on has a `file_path`, so this isn't just an internal guarantee — the user sees it.

Every editor tab gets a `session_id` (a random UUID) at construction. That id — not tab index, not file path — is the stable key threading together the open tab, its draft file on disk, its `index.json` entry, and its row in the drafts sidebar. Tab reordering (drag & drop is enabled) never invalidates this.

There is deliberately **no "unsaved changes?" confirmation dialog for notes that live in `~/.noteeditor`** (untitled notes and files under `docs/`) — closing a tab or quitting archives silently to `drafts/` and proceeds. The drafts sidebar is the safety net that makes this acceptable; don't reintroduce a blocking confirmation for them without reconsidering that tradeoff. **External files** (`is_external_file`/`isExternalFile`: a `file_path` outside `~/.noteeditor`) are the one exception, by explicit user request: closing a *modified* one from `close_tab`/`closeTab` asks Save / Don't save / Cancel (`_ask_save_before_close`/`askSaveBeforeClose`). Quitting still never prompts (`closeEvent` archives everything and the session restores it modified). (Trashing *does* ask for confirmation — that's a deliberate exception, since it removes an entry from `index.json`/the sidebar entirely rather than just archiving silently in the background. Trashing a draft that is currently open — from the tab context menu or the sidebar — first flushes the tab's latest text to `drafts/` (autosave is debounced), then removes the tab *without* going through `close_tab`/`closeTab`, which would re-archive the draft being trashed and resurrect its `index.json` entry.)

Pinned notes: `pinned` lives in `index.json` and is written **only** by `set_pinned`/`setPinned` — `save_session`/`save_draft` (`saveSession`/`saveDraft`) rebuild the rest of an entry on every save and must carry the flag over (`_merged_meta`/`mergedMeta`), otherwise the next autosave silently unpins the note. Blocking is enforced at the single choke point: `close_tab`/`closeTab` returns early for a pinned tab (so the cross, Ctrl+W, the toolbar icon and every bulk close — which all loop over `close_tab` — skip pinned notes for free), and `_trash_draft`/`trashDraftEntry` refuses too; the menu items being greyed out is only cosmetic. Don't add a new way to close a tab that bypasses `close_tab`. Quitting is deliberately *not* blocked (pinned notes come back pinned). The pin is drawn to the *left* of the name using the native icon slot, not a custom widget/delegate: a pinned tab gets the pin as its tab icon and no ✕; in the sidebar it is the list item's icon (grey, white when the row is selected), and unpinned rows get a blank icon of the same size so the names stay aligned. The sidebar keeps its normal horizontal scrolling.

External files and the sidebar: an external file's text lives in the file itself, so the sidebar (`DraftsBrowser.refresh`) lists it **only while it is open** — a closed one is filtered out by `is_external_file`, *not* deleted: its `drafts/` entry, `index.json` entry and `versions/` stay, so reopening it reuses the same `session_id` and the version history continues. After "Don't save" the (hidden) draft is rewritten from disk with `modified=False` (`_archive_unmodified`/`archiveUnmodified`) so abandoned edits don't resurrect on reopen. `close_tab`/`closeTab` returns `False` only when the user cancelled; bulk closes (`close others/right/all`, and the sidebar's multi-selection actions, which all arrive through the single `bulk_action_requested`/`bulkActionRequested` signal → `_handle_bulk_action`/`handleBulkAction`: "close" → `_close_entries`/`closeEntries`, "pin"/"unpin" → `_apply_pinned` per note then **one** `_finish_pin_change`, "trash" → `_trash_entries`/`trashEntries`. Trashing is factored as `_trash_now` (flush text, remove the tab *without* `close_tab`, `trash_draft`) + `_after_trash` so the single and bulk paths share it; the bulk path asks once and skips pinned notes. A refresh rebuilds the list and drops the selection, so pin/unpin re-select the acted-on ids via `select_ids`/`selectIds`) stop at the first `False`, while a pinned note just returns `True` (skipped).

Undo/redo history: Qt cannot export a `QTextDocument`'s undo stack, so `Editor` mirrors it as a list of steps `(start, removed, added)` plus a position (`_track_history`/`trackHistory`, on `contentsChange`). Two facts make this work and must be kept in mind: `undoCommandAdded` fires *before* the `contentsChange` of the same edit (it flags "new step"; without it a change is an undo, a redo — recognised by comparing with the neighbouring step's text — or typing that Qt merged into the last step), and an empty stack (`!isUndoAvailable && !isRedoAvailable`) means `setPlainText` ran, so the mirror resets. `restore_history`/`restoreHistory` validates every step against the current text, then `setPlainText(base)`, replays each step as its own `beginEditBlock` (edit blocks are not merged by Qt) and `undo()`s back to the saved position; any mismatch discards the history and leaves the text alone. Do not add a step-drop while tracking (the mirror must stay 1:1 with Qt's stack; trimming happens only in `history_state`/`historyState`). A step must never split a UTF-16 surrogate pair (C++ `diffTexts` guards this; Python works on code points and skips the file if encoding fails). Notes above 300 000 characters are not tracked.

Markdown preview scroll sync and HTML export: the preview follows the *active* editor's vertical scrollbar proportionally (`_sync_preview_scroll`/`syncPreviewScroll`: `value/max` of the editor → same ratio of the preview's range). Each editor's `valueChanged` is connected with a check that the editor is the current one (a hidden tab restoring its scroll must not move the preview), and the preview scrollbar's `rangeChanged` also re-syncs — `QTextBrowser` settles its range *after* `setMarkdown`, so a sync done right after rendering uses a stale maximum. `export_html`/`exportHtml` (File menu, enabled only for Markdown tabs) writes `QTextDocument.setMarkdown(current text).toHtml()` as UTF-8 (title = file name), defaulting to the Markdown file's folder so relative image paths stay valid.

Restoring the scroll position: a tab that has never been displayed has no scrollbar range yet (clamping any `setValue` to 0), so `Editor.restore_view`/`restoreView` sets the cursor immediately but keeps the scroll as *pending* and applies it on the first `showEvent` (deferred one event-loop turn). `view_state`/`viewState` therefore reports the pending value while it is unapplied — otherwise quitting again before ever showing that tab would overwrite the saved scroll with 0. Restore the cursor *before* the scroll: `setTextCursor` scrolls the cursor into view.

Save As onto a known file: `_write_file`/`writeFile` first calls `_adopt_existing_draft`/`adoptExistingDraft`. If a *closed* note already exists for the target path (`find_draft_for_path`), the saved note **adopts its `session_id`** (the old untitled draft is deleted, `versions/` are merged with `merge_versions`, `pinned` is the OR of both) instead of leaving two entries for one file. Skipped when the target is the note's own file or when the existing note is open in another tab.

One draft per file: opening a file (`_open_path`/`openPath`, i.e. Ctrl+O and drag & drop) must **reuse** the existing draft bound to that `file_path` (`find_draft_for_path`/`findDraftForPath`, newest first) instead of minting a new `session_id` — otherwise every open/close cycle of the same file adds another sidebar entry (and orphans its version history, which is keyed by `session_id`). If that draft has unsaved edits (`modified`), reopen the draft as-is; otherwise re-read the file from disk under the same id. Opening a draft from the sidebar (`_open_draft`/`openDraft`) also switches to an already-open tab for the same file instead of opening a second tab on it. Older data may still contain duplicate entries for one file; they are left alone (the user trashes them).

Content search in the sidebar: `DraftsBrowser.refresh` also matches the filter against the note's *draft file* text (`_content_matches`/`contentMatches`), cached per draft by (mtime, size) and cleared whenever the search field is emptied so the texts don't stay in memory. It reads `drafts/<id>.txt` (≤ 1.5 s stale for a note being typed in), and only covers what the sidebar lists — a hidden closed external file is not searched.

Pinned tabs are kept grouped on the left: `_normalize_tab_order`/`normalizeTabOrder` is a *stable partition* using `QTabBar.moveTab` (the current tab follows its widget). It runs from `_finish_pin_change`, when a pinned note is (re)opened, at the end of session restore — where the active tab must therefore be found **by id**, not by index — and after a manual drag. The drag case is handled with an event filter on the tab bar's `MouseButtonRelease` (deferred with a 0 ms timer), **not** from `tabMoved`: that signal fires for every intermediate step of the gesture, and undoing moves mid-drag fights Qt's own drag state.

Sidebar behavior: it lists every draft in `index.json`/on disk, open or closed — currently-open ones get a `(ouvert)` suffix rather than being hidden. Clicking an already-open one switches to it instead of duplicating the tab. Renaming (right-click) only applies to untitled drafts (no `file_path`) — it's rejected/hidden for anything backed by a real file, since renaming *that* would mean either renaming the file on disk or diverging the label from the actual filename, neither of which this feature is meant to do.

### The tab-bar "+" button

Both implementations maintain **two** separate button widgets for "new tab" (an inline one and a corner-widget one), not one, toggled based on whether the tab bar is currently overflowing into scroll arrows. This looks redundant but isn't: Qt has no reliable way to place a widget "just after the last tab" that also survives the tab bar overflowing. The split — inline child positioned via manual `.move()` math while tabs fit; a `QTabWidget` corner widget (which overrides `sizeHint()` rather than using `setFixedSize()`, because Qt silently collapses a corner widget's height to 0 otherwise) once they overflow — was arrived at after several failed single-widget approaches, in both languages independently. If touching this code, re-test both the "few tabs" and "many tabs, scroll arrows visible" cases, not just one.

`QApplication::setStyle("Fusion")` (or `app.setStyle("Fusion")` in Python) is forced at startup in both — without it, some native/GTK Qt styles silently ignore parts of the custom QSS (this was root-caused, not a stylistic preference). Removing it will reintroduce theme-dependent rendering bugs.

### Syntax highlighting

Extension → highlighter selection happens whenever a tab's associated file path changes (open, Save As to a new extension). Colors are tuned for a **light** background only — there's no dark-mode variant yet (see `IMPROVEMENTS.md`).
